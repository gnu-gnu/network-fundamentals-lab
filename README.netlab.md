# Netlab — 브라우저 기반 네트워크 실습 플랫폼

Netlab은 이 저장소의 네트워크 트러블슈팅 실습을 웹으로 제공하는 셀프호스팅 플랫폼입니다.
학습자는 브라우저에서 환경을 시작하고, 터미널로 고장 난 네트워크를 관찰·수정합니다.
운영자는 LXD VM의 생성·정지·초기화·회수와 녹화·백업을 관리합니다.

학습자 PC에 Docker나 containerlab을 설치할 필요는 없습니다.
실습은 서버의 VM 안에서 실행되며, 네트워크 토폴로지는 그 VM 내부의 컨테이너로 구성됩니다.

기본 설치는 **로그인 없는 공용 `guest` 환경**입니다. 외부 공개, TLS, 인증은 설치자가
선택합니다. 공용 모드의 접속자들은 같은 VM·터미널·파일을 공유하므로 개인별 환경으로
오해하지 않도록 주의하세요. 관리자 웹/API와 root 전용 관리 CLI는 공개하지 않습니다.

- [상세 설치·업데이트·백업 안내](server/README.md)
- [운영 참고 문서](server/OPERATIONS.md) — 기존 인증 기반 운영 환경의 사례 포함

## 제공하는 기능

- 브라우저 패널에서 실습 VM 발급·시작·정지·초기화·영구 종료
- ttyd 기반 웹 터미널과 챕터 이동·노드 접속용 단축 명령
- 세션 녹화, 리플레이, 명령 타임라인과 학습 기록 수집
- 유휴 정지·장기 미사용 환경 회수, 선택적인 예비 VM 풀
- 선택적인 Cloudflare Access JWT 검증과 개인별 계정·역할 관리
- root 전용 계정 관리, 녹화 관리, 암호화 백업·빈 서버 복원 CLI
- 실습 상태·대화 이력을 활용하는 선택적인 AI 튜터

전체 챕터의 자동 채점은 완성된 기능이 아닙니다. LLM 도움말에는 별도의 endpoint·모델·키
설정이 필요하며, 이를 설정하지 않아도 일반 실습은 사용할 수 있습니다.
AI 헬퍼는 관리 서버의 `/etc/netlab/tutor.json`에서 설정합니다.
[모델 연결과 추론 옵션 설정](server/README.md#ai-헬퍼-설정)을 참고하세요.
00~17장(OSPF/BGP 포함)의 진단 정보를 제공하며 관찰·탐구형 실습은 단일 성공 조건으로
채점하지 않습니다. 튜터는 명령을 제안할 수 있지만 자동으로 실습을 수정하지 않습니다.
현재 장의 가이드와 관련 절·개념 Wiki를 참고해 답하고, 출처와 원문을 함께 제공합니다.

## 실행 구조

```text
학습자 브라우저
    │ HTTP :8088 (TLS·외부 프록시·인증은 선택)
    ▼
Ubuntu 호스트
    ├─ Nginx                 웹 진입점, 패널·터미널 프록시
    ├─ labd                  Python 프로세스, systemd 서비스
    │   └─ 127.0.0.1:9000    관리 API·UI·VM 수명 관리
    └─ LXD                   VM 생성, 네트워크, ZFS 스토리지
        └─ 실습 VM           Ubuntu + ttyd + 녹화 + 실습 콘텐츠
            └─ Docker / containerlab
                └─ 라우터·스위치·호스트 역할의 실습 컨테이너
```

관리 서버는 Docker 컨테이너나 컴파일된 단일 바이너리가 아니라 **호스트에서 실행되는
Python/systemd 서비스**입니다. LXD도 같은 호스트에 설치됩니다. Docker는 기본 설치 시
실습 VM 내부에 설치하며, 호스트에 별도로 설치하지 않습니다.

## 빠른 시작

### 1. 서버 준비

- Ubuntu 24.04, x86_64
- 하드웨어 가상화와 `/dev/kvm` 사용 가능
- VM에 설치한다면 중첩 가상화 활성화
- 패키지·Ubuntu 이미지·컨테이너 이미지 다운로드를 위한 인터넷 연결
- 기본 ZFS 파일 기반 풀 100GiB와 설치기가 요구하는 추가 여유 10GiB 이상
- 실습 VM 기본값인 2 vCPU·4GiB RAM에 더해 호스트와 이미지 빌더를 실행할 자원

실습 VM의 기본 가상 디스크 크기는 50GiB이며 실제 사용량과는 다릅니다.
동시에 실행할 VM 수와 백업 임시 공간까지 고려해 서버 용량을 확보하세요.
Cloudflare 계정이나 공개 도메인은 기본 설치에 필요하지 않습니다.

### 2. 설치

서버에서 이 저장소를 checkout한 뒤 저장소 루트에서 실행합니다.

```bash
# 요구사항과 계획만 확인 — 변경하지 않음
sudo python3 server/bootstrap.py

# LXD부터 실습 골든 이미지·웹 서비스까지 설치
sudo python3 server/bootstrap.py --apply
```

설치기는 LXD, 스토리지, 전용 네트워크·프로필, 격리용 방화벽, 골든 VM 이미지,
Nginx와 관리 서비스를 준비합니다. 골든 이미지는 실제 01장 컨테이너 배포와 ping 검사를
통과한 뒤 발행합니다. 최초 설치에는 이미지 다운로드와 빌드 시간이 필요합니다.

기존 같은 이름의 리소스가 호환되지 않으면 덮어쓰지 않고 중단합니다. 물리 디스크를
포맷하거나 기존 LXD 구성을 초기화하지 않습니다. 스토리지 크기·네트워크 대역 변경은
[설치 옵션](server/README.md#새-ubuntu-서버-자동-설치)을 참고하세요.

### 3. 접속

```text
http://서버IP:8088
```

기본은 `0.0.0.0:8088`에서 로그인 없이 접속합니다. 브라우저에서 **시작**을 누르면
공용 `guest` VM이 발급됩니다. VM 안에 플랫폼을 설치했다면 위 주소의 서버 IP는
그 VM의 IP입니다. 해당 주소에 도달할 수 없는 네트워크에서는 설치자가 라우팅이나
포트 전달을 구성해야 합니다. 설치기가 공유기·클라우드 방화벽을 자동으로 열지는 않습니다.

## 첫 실습

웹 터미널에서 다음 순서로 시작합니다.

```bash
labs          # 실습 목록
doc 01        # 01장 설명
lab 01        # 토폴로지 배포
n h1          # h1 노드 셸로 진입
# 문제 설명에 따라 진단·수정
exit          # 실습 VM 셸로 돌아오기
unlab         # 현재 토폴로지 철거
```

`walk 01`은 해설, `help-lab`은 단축 명령 안내입니다. 먼저 직접 진단한 뒤 해설과
비교하는 것을 권장합니다. 챕터별 목표와 명령은 해당 폴더의 README를 따릅니다.

- **일시 정지:** VM 디스크의 작업을 남기고 실행을 멈춥니다.
- **다시 시작:** 정지된 VM을 켭니다.
- **초기화:** 깨끗한 스냅샷으로 되돌리므로 이후 작업이 사라집니다.
- **영구 종료:** VM을 삭제합니다.

기본 설정은 유휴 24시간 후 정지, 정지 상태 7일 후 회수입니다. 운영자가 바꿀 수 있으므로
VM을 영구 저장소로 사용하지 마세요. 공용 모드에서는 다른 접속자의 정지·초기화도 같은
환경에 영향을 줍니다. 터미널은 녹화되므로 비밀번호·개인 키 등 비밀값을 입력하지 마세요.

## 접속과 인증 선택

| 구성 | 사용자 환경 | 설치자의 작업 |
|---|---|---|
| 기본 공개 모드 | 로그인 없이 공용 guest VM 공유 | 접근 가능한 네트워크 범위 제한 |
| 외부 프록시·인증을 앞에 추가 | 별도 신원 연동이 없으면 여전히 공용 guest | TLS·프록시·접근 정책 직접 구성 |
| 제공되는 Cloudflare Access 연동 | JWT로 확인한 계정별 VM | Access 설정 인자 지정, Tunnel·도메인·정책 별도 구성 |

Cloudflare는 필수 의존성이 아닙니다. 다른 인증 제품을 앞에 둘 수도 있지만, 그 제품의
사용자 신원을 Netlab의 개인별 계정에 자동 연결하는 범용 연동은 제공하지 않습니다.
Cloudflare 사용 방법과 기존 설치의 인증 모드 전환은
[상세 안내](server/README.md#새-ubuntu-서버-자동-설치)를 참고하세요.

인터넷에 공개하기 전에는 설치자가 인증·TLS·방화벽 정책을 정해야 합니다. 기본 모드에
접근 가능한 사람은 누구나 공용 실습 환경을 조작할 수 있습니다. VM·네트워크 격리 설정은
있지만, 공개된 익명 사용자를 대상으로 한 보안 보증을 의미하지는 않습니다.

## 업데이트와 데이터 관리

검토한 새 소스를 서버에 반영한 뒤 실행합니다.

```bash
sudo python3 server/deploy.py --check
sudo python3 server/deploy.py --apply
```

업데이트는 기존 설정·사용자·VM·녹화를 보존하고 서버 코드를 교체합니다. 관리 서비스는
잠깐 중단됩니다. **서버 코드 업데이트만으로 기존 VM 안의 실습 콘텐츠가 바뀌지는 않습니다.**
새 VM에 변경된 실습을 제공하려면 골든 이미지 갱신 절차를 따르세요.

| 데이터 | 저장 위치 |
|---|---|
| 서버 설정·인증 시크릿 | `/etc/netlab/` |
| 사용자·VM 할당 상태·수집된 녹화 | `/var/lib/netlab/` |
| 실행 코드 | `/opt/netlab-admin/` |
| VM 디스크·스냅샷 | LXD의 `labpool` |
| 배포 롤백·복원 전 파일 | `/var/backups/netlab/` |

관리 CLI는 `netlab-user`, `netlab-record`, `netlab-backup`입니다. root 권한으로 사용하며,
설정·시크릿·백업 비밀번호를 Git에 넣지 않습니다. 배포 시 생성하는 코드 롤백 사본은
사용자 데이터나 VM 전체 백업을 대신하지 않습니다.

## 백업과 이전

```bash
# /안전한백업경로는 미리 준비한 실제 디렉터리로 바꿉니다.
sudo netlab-backup create --mode full --output /안전한백업경로/full.gpg
sudo netlab-backup inspect /안전한백업경로/full.gpg
```

비밀번호는 대화식으로 입력합니다. `full`은 설정·사용자·녹화와 관리 대상 VM·스냅샷·
골든 이미지를 포함합니다. `config`는 VM 디스크를 제외하며, 복원 시 VM 할당 상태를 비웁니다.
전체 백업 동안 실행 중인 실습 VM을 정상 종료했다가 다시 시작하므로 사전 공지가 필요합니다.

복원은 동일한 코드와 호환되는 인프라를 준비한 **빈 서버**를 대상으로 합니다.
`restore --dry-run`으로 먼저 검사하며 기존 사용자·VM이 있는 대상에는 덮어쓰지 않습니다.
큰 디스크와 스냅샷은 백업·복원 시간이 길 수 있습니다. 비밀번호와 백업은 분리 보관하고,
원본을 폐기하기 전에 복원된 실습을 확인하세요.

[암호화·임시 공간·복원 준비·실패 시 대응](server/README.md#암호화-백업과-빈-서버-복원)

## 문제 확인과 개발 검증

개발 VM 접속 방법과 배포 절차는 저장소에 포함하지 않는 내부 문서(`server/local/DEVELOPMENT.md`)로 관리합니다.

```bash
sudo systemctl status labd nginx
sudo journalctl -u labd -n 100 --no-pager
sudo lxc list
sudo lxc image list
```

접속이 안 되면 서버 IP·8088 포트·방화벽·VM까지의 경로를 확인합니다. 이미지 생성 실패는
`/var/lib/netlab-bootstrap/guest-build.log`를 확인합니다. 로그를 공유할 때는 개인정보와
비밀값이 없는지 먼저 검토하세요. 데이터 디렉터리 삭제나 LXD 전체 초기화로 해결하지 마세요.

저장소의 소스 검증은 다음 명령으로 실행합니다. 암호화 테스트에는 GnuPG가 필요합니다.

```bash
python3 server/deploy.py --source-check
python3 -m unittest discover -s server/tests -v
```

Ubuntu 24.04 중첩 VM에서 클린 설치와 별도 빈 서버로의 전체 백업 복원을 검증했습니다.
검증 범위와 제한은 [상세 안내](server/README.md)를 참고하세요.

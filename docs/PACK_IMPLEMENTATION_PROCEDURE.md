# 학습 팩 v2 구현 절차

작성 기준: 2026-10-24. 상태: 합의된 개발 계획이며 구현 완료 보고가 아닙니다.

이 문서는 학습 팩 v2를 M1부터 M4까지 구현하고 검증하는 순서를 정합니다. 반드시 지켜야 하는 동작은 [구현 계약](PACK_IMPLEMENTATION_CONTRACTS.md), 실행기 요청 형식은 [JSON Schema](schemas/netlab-runner-request.schema.json)를 따릅니다. 내부 검토 문서를 별도로 읽을 필요가 없도록 최종 결정을 수록했습니다.

## 목표와 범위

첫 결과는 개발 환경에서 12장 PMTUD를 **시작 → 미통과 확인 → 수동 수정 → 통과 확인 → reset → 미통과 확인**하는 것입니다. 이때 단계 본문·힌트가 보이고 진행 이벤트가 남아야 합니다. 호스트 서비스 분리나 운영 이미지 빌드를 먼저 끝내야 하는 구조로 만들지 않습니다.

| 단계 | 학습자에게 보이는 결과 | 주요 구현 |
| --- | --- | --- |
| M1 | 12장 단계별 실습과 확인 버튼 | 컴파일·실행기·프로세스 내부 client·진행 DB·최소 작업 관리·UI·개발 설치 |
| M2 | CLI 실습 연결과 현재 상태를 아는 튜터 | solve, adopted_cli, job 조회 고도화, 17장·shell·03 검증, 튜터 컨텍스트 |
| M3 | 승인된 운영 파일럿 | runner 포함 이미지, bundle 정합성, 풀 이행, 백업·복구, 롤백 |
| M4 | 전체 네트워크 과정과 개념 확인 | 19레슨 이행, reflect·quiz·서버 전용 grading, 공개 팩 저작 스펙 |
| 후속 | 운영 구조와 추가 런타임 | 별도 호스트 서비스, compose, 서비스 탭, 터미널 입력 삽입 |

M1은 start/status/check/reset/stop만 제공하고 solve는 수동 명령으로 대신합니다. 서비스 탭·checkpoint·배지·외부 팩 설치는 범위 밖입니다. 현재 인증, 모델 목록·설정, 채팅, 테마, 녹화는 유지합니다. 운영 반영은 M3부터 별도 승인 후 수행합니다.

## 착수와 기준선

1. 사용자에게 M1 구현 착수 승인을 받습니다. 이 문서 작성·커밋만으로 구현이나 운영 배포가 승인된 것은 아닙니다.
2. 작업 트리와 index를 확인하고 다른 세션의 변경을 자동 커밋·stash·복구하지 않습니다. 승인된 소스 스냅샷과 해시 또는 합의된 커밋을 비교 기준으로 기록합니다.
3. v1 카탈로그 19레슨의 ID·assessment·checks·fallback·probes·교재 대응을 고정합니다. 같은 레슨을 다시 선택하면 컨테이너를 보존하는 기존 동작도 기준으로 둡니다.
4. 개발 환경에 사용자가 할당되지 않은 전용 검증 VM을 준비합니다. 이름뿐 아니라 개발 환경 식별, 전용 라벨, 소유 기록, 미할당 상태를 확인합니다.
5. 기존 테스트를 실행해 시작 시 실패와 이번 변경으로 생긴 실패를 구분합니다. 실제 모델 호출과 운영 VM 조작은 기본 검사에 포함하지 않습니다.

기존 검증 기반은 [팩 테스트](../server/tests/test_packs.py), [교재 검색 비교](../server/tests/equivalence_retrieval.py), [HTTP 비교](../server/tests/equivalence_http.py), [실습 전환 검사](../server/tests/integration_lab_switch.py)입니다. 신규 화면의 의도된 차이까지 바이트 단위로 같게 만들지 않고, 유지해야 하는 v1 경로와 새 경로를 구분해 검사합니다.

## M1 구현 순서

아래 신규 경로는 구현 시 만들 대상이며 현재 기능이 존재한다는 뜻이 아닙니다. 한 레슨을 끝까지 연결하는 순서로 진행하고 각 하위 단계에서 개발용 화면으로 결과를 확인합니다.

### 컴파일과 호환 번들

- `server/packctl.py`, `server/pack_format/`: 12장 v1 변환, 스키마 검사, recipe 생성, revision 계산, 호환 번들.
- 기존 `server/build_knowledge.py`의 진입점은 호환 래퍼로 유지하고 `server/packs.py`에는 정식 ID와 별칭 해석을 추가합니다.
- 원본 레슨 디렉터리를 이동하지 않고 별도 출력에 v2를 생성합니다. 같은 레슨이 v1/v2로 중복 등록되지 않도록 선택된 버전만 카탈로그에 넣습니다.
- README·WALKTHROUGH·토폴로지의 로컬 참조를 검사하고 `fix.sh`를 포함합니다. 모호한 동적 셸 참조는 자동으로 안전하다고 판단하지 않고 실기 확인 대상으로 남깁니다.
- 생성 중인 파일을 현재 카탈로그에 덮어쓰지 않습니다. 전체 검사 후 생성물 묶음을 전환합니다.

완료 기준: 12장 recipe와 bundle이 검증되고, `fix.sh`가 보존되며, 원본 TOML·grading·제외 파일이 들어가지 않습니다. 같은 입력의 재빌드는 같은 revision을 만들고 실행 파일 내용 변경은 revision을 바꿉니다.

### 실행기와 프로세스 내부 경계

- `server/netlab-runner`, `server/runner/`: 요청 검증, 영속 상태, 비차단 변경 잠금, check 취소, containerlab 어댑터, 결과 분류.
- `server/netlab/agent_client.py`: 첫 구현은 labd 프로세스 내부 클래스입니다. 소유권·환경·등록 ID 검사 후 고정 runner subcommand를 호출합니다. 범용 argv·경로 전달 API는 만들지 않습니다.
- 요청 스키마가 통과해도 실제 소유권·토큰·bundle·capability를 별도로 확인합니다.
- request_id 중복 방지와 미완료 작업 표식은 M1에 포함합니다. 전체 결과 저널과 연결 단절 후 결과 회수는 선행 조건이 아닙니다.
- M1부터 장시간 작업의 최소 job 상태와 조회 경로를 제공해 HTTP 요청을 완료까지 붙잡지 않습니다. M2의 job 고도화와 구분합니다.

완료 기준: 오래된 start·stop도 거절되고, 같은 레슨 start는 no-op이며, 완료 후 reset·stop이 가능합니다. 변경 작업끼리는 busy이고 검증 취소는 종료 확인 후에만 변경으로 이어집니다.

### 진행 DB와 단계 화면

- `server/netlab/lessons.py`, `lesson_progress.py`: API, 회차·이벤트·최초 완료, 최소 요청 중복 방지.
- `server/labd.py`는 기존 인증과 라우팅을 유지하고 레슨 처리를 새 모듈에 위임합니다.
- `server/templates/panel.html`, `guide_view.py`, `assets/lesson.js`, `assets/lesson.css`: 단계 본문, 확인, 힌트, 진행 중·실패·완료 표시.
- 작업 API는 검증된 사용자에서 대상을 결정하고 attempt/job 조회도 소유권을 검사합니다.
- 넓은 화면은 터미널 옆 공간을 사용하고 좁은 화면에서는 위아래 또는 전환 표시로 배치합니다. 터미널을 가리는 오버레이를 기본 레이아웃으로 사용하지 않습니다.
- 코드 블록은 미리보기와 복사만 제공합니다. iframe의 xterm 접근 가능 여부와 안전한 명령 입력은 별개이며 자동 삽입·실행은 하지 않습니다.

완료 기준: 첫 마일스톤에서 실제 단계 UI를 사용할 수 있고 확인 결과가 DB에 기록됩니다. 터미널 입력, 테마, 전체화면, 튜터·채팅 버튼의 기본 동작은 깨지지 않습니다.

### 개발 전용 설치

`packctl install --instance <검증 VM>`을 구현합니다. 개발 환경·전용 라벨·미할당·관리 대상 여부를 모두 검증하고 진행 중 실습 작업이 있으면 거부합니다. runner와 bundle을 staging에 올려 검증한 뒤 일관되게 전환하며 실패하면 이전 설치를 유지합니다.

설치는 사용자가 할당되기 전에 수행합니다. 브라우저 실기 테스트는 설치 후 전용 테스트 계정에만 연결하고, 다시 설치하려면 작업과 할당을 정리해 미할당 조건을 재확인합니다. 운영 VM에는 이 명령을 사용하지 않으며 운영은 검증된 이미지로 배포합니다.

### M1 수용 테스트

| 번호 | 시나리오 | 합격 조건 |
| --- | --- | --- |
| M1-01 | 개발 VM에서 12장 시작·확인·수동 수정·확인·reset·확인 | fail → pass → fail, 화면과 이벤트 일치 |
| M1-02 | 같은 레슨 start 재호출 | 컨테이너 ID·작업 파일·generation 유지 |
| M1-03 | 예전 토큰의 start/reset/stop | 실행 전 conflict, 현재 환경 변경 없음 |
| M1-04 | 같은 request_id 재전송·다른 내용 재사용 | 같은 요청은 중복 실행 없음, 다른 내용은 거부 |
| M1-05 | 긴 check 중 reset/stop | 검증 종료 확인 후 변경, cancelled와 늦은 pass 집계 제외 |
| M1-06 | 취소할 수 없는 check | 변경하지 않고 cancel_failed 또는 recovery_required |
| M1-07 | 상태 파일 삭제·손상·재부팅 중단 | 자동 전체 철거 없이 명확한 복구 안내 |

| M1-11 | 변경된 화면의 좁은·넓은 배치 | 가로 넘침·터미널 입력 방해 없음 |
| M1-12 | 개발 install의 비개발·할당 VM 대상 | 변경 없이 거부 |

M1-01은 **전용 검증 VM에서 실행하는 실기 검사 한 벌**로 남깁니다. 수동 복구에는 기존 [12장 fix.sh](../12-mtu-pmtud/fix.sh) 또는 해설 명령을 사용합니다. 이 문서가 해당 명령을 운영에서 실행하라는 지시를 뜻하지 않습니다.

## M2 확장

1. solve와 CLI 환경 연결을 추가합니다. CLI로 시작한 레슨을 회차에 연결할 때 runner.start를 호출하지 않습니다. CLI check는 참고용이며 공식 진행에 반영하지 않습니다.
2. 17장 OSPF/BGP로 다중 레슨을, shell 예제로 비containerlab 실행을 검증합니다. 03장으로 복수 조건 검증을 보강합니다.
3. job 조회·오류 표시와 재접속 복구를 고도화합니다. 불확실한 중단 작업을 자동 재실행하지 않습니다.
4. `netlab_tutor.py`, `tutor_chat.py`, `knowledge.py`에 레슨·회차·세대·단계·revision 컨텍스트를 연결합니다. 모델 설정은 유지합니다.
5. 레슨 전환 중 도착한 튜터 응답은 과거 환경의 설명임을 표시합니다. LLM이 solve/reset이나 임의 명령을 실행할 수 없도록 합니다.

완료 기준: `lab 04`와 같은 CLI 사용 흐름을 새 환경에서 재배포 없이 웹에 연결할 수 있습니다. 첫 질문부터 현재 레슨을 설명하고, 12·17·shell·03의 판정과 fallback·오류 분류가 기대값과 일치합니다.

## M3 운영 파일럿

### 이미지와 기존 VM 이행

- bootstrap의 bundle 설치와 runner 포함 이미지를 구현하고 fingerprint, runner/protocol, pack/bundle map을 기록합니다.
- 새 이미지를 별도 이름으로 검증한 뒤 승인된 할당 경로에 연결합니다. 기존 이미지·VM을 자동 삭제하거나 alias만 보고 호환으로 간주하지 않습니다.
- runner 없는 VM은 레슨 API에 410과 갱신 안내를 반환합니다. 기존 터미널·튜터·동결된 v1 check는 이행 기간 유지합니다.
- runner 고장·protocol 불일치·bundle 오류는 v1 자동 우회 사유가 아닙니다. 해당 오류와 복구 경로를 표시합니다.
- 계정별 실행 플래그는 두지 않습니다. 상태 API는 서버가 확인한 capability와 경로를 표시합니다. 전역 접수 차단은 긴급 중지에만 사용합니다.

일반 초기화는 [restore_for](../server/netlab/instances.py)의 같은 VM clean 스냅샷 복원입니다. 최신 이미지로의 업그레이드가 아닙니다. 업그레이드는 작업 사본·녹화를 보전하고 기존 파기·풀 재발급 절차를 명시적으로 수행합니다. 복원·교체 시 incarnation을 갱신합니다.

### 백업과 롤백

기존 [백업 도구](../server/netlab-backup)는 `/var/lib/netlab`을 포함하므로 새 백업 체계부터 만들지 않습니다. 진행 DB는 SQLite backup API의 일관된 사본으로 포함하고 라이브 WAL/SHM을 섞지 않습니다. 빈 전용 환경에서 무결성·외래키·회차와 이벤트 관계를 검사합니다. 복원된 진행은 VM 상태와 동기화하고 running job을 자동 재실행하지 않습니다.

릴리스 기록에는 소스 기준, 문서·스키마 판, catalog/pack/bundle revision, 이미지 fingerprint, runner/protocol, 테스트 결과, 백업 복원 결과, v1 제거 목표일·관찰 기간을 포함합니다. 운영 접속 주소·비밀값·사용자 목록은 공개 문서에 넣지 않습니다.

문제가 생기면 새 v2 접수를 막고 작업 상태를 확인한 뒤 코드를 롤백합니다. 새 DB·사용자 작업·VM을 삭제하지 않습니다. v2 VM을 구버전 실행 경로로 억지 처리하지 말고 종료·복구·교체를 선택합니다. 자료형 변경은 기존 이력을 읽을 수 있는 추가형 이행부터 적용합니다.

### 운영 반영 조건

M1·M2와 이미지·백업·복구 테스트를 통과하고 **사용자 승인을 받은 뒤** 선정된 운영 파일럿에 반영합니다. 운영에서 일반 사용자의 실습을 대상으로 파괴적 검증을 하지 않습니다. 이후 확대 반영도 승인된 범위에서 수행합니다.

v1 경로는 다음을 모두 만족할 때 제거합니다.

1. 마지막 사용자 v1 VM과 풀의 v1 후보를 정리했습니다.
2. 작업 사본·녹화 보전 및 v2 이용을 확인했습니다.
3. 승인 시 정한 롤백 관찰 기간이 끝났습니다.

ID 별칭과 과거 학습 이력 해석은 유지합니다. 날짜만으로 사용자 VM을 강제 파기하지 않습니다.

## M4 전체 과정과 개념 확인

19레슨의 ID·check·fallback·자료·CLI 참조를 검증한 뒤 이행합니다. 자료 이동을 먼저 하지 않고 생성된 호환 데이터로 검증합니다. 관찰형에 가짜 성공 조건을 만들지 않으며 solve가 없는 레슨을 실행하지 않은 테스트까지 통과한 것으로 표시하지 않습니다.

reflect와 quiz를 추가합니다. 정답·채점 규칙은 서버 전용이고 API·튜터·VM에 노출하지 않습니다. read/quiz/reflect의 종류·회차 소유권을 검증하며, 단계 공개와 실제 이해 평가를 구분합니다. 튜터 DB의 기존 chapter는 먼저 조회 시 별칭으로 해석해 일괄 이력 변경을 선행하지 않습니다.

실제 구현과 파일럿 결과에 맞춰 팩 저자용 `docs/PACK_FORMAT.md`와 실행 가능한 예제를 작성합니다. 이 절차서·계약서는 구현 기준이며 완성된 팩 저작 스펙을 대신하지 않습니다.

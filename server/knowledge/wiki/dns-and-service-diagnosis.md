# DNS 성공, TCP 연결, 서비스 성공의 구분

## DNS와 서비스는 서로 다른 확인 대상이다

DNS가 IP 주소를 답한다고 해서 해당 주소의 서비스가 살아 있다는 뜻은 아니다.
권한 서버의 레코드를 수정해도 재귀 캐시에 TTL 동안 옛 응답이 남을 수 있다.
권한 응답과 캐시 응답, 실제 HTTP 응답을 각각 확인해야 한다.

다중 A 레코드에 죽은 주소가 섞이면 주소 선택과 재시도 방식에 따라 지연이나 간헐 실패가
나타날 수 있다. 한 번의 성공만으로 모든 레코드의 서비스가 정상이라고 판정하지 않는다.

## TCP 증상을 해석할 때

SYN 뒤 무응답과 RST는 다른 증상이다. 서버에 리스너가 없을 때와 중간 방화벽이
tcp-reset으로 거절할 때 모두 RST가 나올 수 있다. 패킷 출처와 서버 리스너를 함께 본다.
ICMP도 진단용 echo 외에 경로 오류와 MTU 정보를 전달하므로 전면 차단의 영향을 구분한다.

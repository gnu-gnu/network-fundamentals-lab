# L2 전달, ARP, VLAN의 구분

이 문서는 아래 실습 원문을 연결해 정리한 개념 문서다. 현재 VM의 상태를 설명하는 문서는 아니다.

## 다음 홉과 MAC 주소

호스트는 라우팅으로 출력 인터페이스와 다음 홉을 선택한다. 이더넷에서 IPv4 다음 홉의
MAC 주소가 필요하면 ARP로 알아낸다. 같은 서브넷의 직접 연결 목적지는 보통 목적지 자체가
다음 홉이고, 다른 서브넷은 보통 게이트웨이가 다음 홉이다. 게이트웨이 MAC을 아는 것만으로
라우터 너머의 왕복 경로나 방화벽 통과가 보장되지는 않는다.

## 스위치 학습은 별개다

스위치는 수신한 프레임의 출발지 MAC과 포트를 학습한다. ARP 프레임도 학습의 재료지만
ARP가 스위치 학습을 수행하는 것은 아니다. 목적지 MAC을 알면 해당 포트로 전달하고,
모르는 유니캐스트나 브로드캐스트는 해당 VLAN 범위에서 플러딩할 수 있다.

## 흔한 혼동

- 같은 L2에 있어도 서로 다른 IP 서브넷으로 설정할 수 있다. 두 개념은 동일하지 않다.
- 같은 IP 서브넷으로 설정해도 VLAN이 다르면 보통 직접 ARP가 전달되지 않는다.
- 트렁크의 VLAN 허용이 한쪽에 빠지면 해당 VLAN만 실패할 수 있다.
- containerlab의 eth0 관리망은 실습용 eth1 이후의 데이터 경로와 구분한다.
- L2 루프에는 IP TTL이 적용되지 않는다. STP와 링크 절단은 서로 다른 대응이다.
